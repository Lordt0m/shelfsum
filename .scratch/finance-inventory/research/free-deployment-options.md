# Free deployment options for ShelfSum (checked 2026-09-17)

## Recommendation

Use **Render Free Web Service + Neon Free Postgres**:

`GitHub -> Render web service (Django/Gunicorn/WhiteNoise) -> Neon Postgres`

This is the best match for a recruiter-facing demo because Render supplies a public HTTPS URL, Git-based Python builds, environment variables, and a free web runtime without requiring payment in its first-deploy guide; Neon supplies the durable PostgreSQL database without a card requirement. Do **not** use Render Free Postgres: it is limited to 1 GB and expires after 30 days, then data is deleted after a 14-day upgrade grace period. Sources: [Render first deploy](https://render.com/docs/your-first-deploy), [Render free limits](https://render.com/docs/free), [Neon current free-plan announcement](https://neon.com/blog/building-patterns-unlocked-by-scale-to-zero).

Fallback: **Koyeb Free Web Service + Neon Free Postgres**. It is technically workable and has a free public HTTPS `koyeb.app` domain, but Koyeb requires a credit card for account validation, so it is second choice for this user. Sources: [Koyeb pricing FAQ](https://www.koyeb.com/docs/faqs/pricing), [Koyeb Django deployment](https://www.koyeb.com/docs/deploy/django), [Koyeb TLS](https://www.koyeb.com/docs/reference/edge-network).

### Practical deployment shape

The repository currently declares only `Django==5.2.17`; deployment will therefore need the normal production dependencies/configuration (a PostgreSQL driver such as `psycopg`, Gunicorn, WhiteNoise, `DATABASE_URL`/SSL, `ALLOWED_HOSTS`, and `collectstatic`) before it can run on either host. Render's Django guide explicitly uses PostgreSQL, WhiteNoise, and a build script; Koyeb's guide uses Gunicorn and WhiteNoise. Sources: [Render Django guide](https://render.com/docs/deploy-django), [Koyeb Django guide](https://www.koyeb.com/docs/deploy/django).

For Render Free, use `build.sh` as the build command. Render's pre-deploy command is documented as paid-only, and Free web services have no shell/one-off jobs. Because ShelfSum's `python manage.py seed_demo` command is deterministic and idempotent, it verifies and preserves the canonical fictional dataset without duplicating records while intentionally resetting the two published Demo passwords to their canonical values on each verified run. It safely remains in `build.sh` alongside migrations and static collection across repeated deployments. Render documents build/start commands and environment variables, and the project already has a `seed_demo` management command. Sources: [Render deploy lifecycle](https://render.com/docs/deploys), [Render SSH/shell availability](https://render.com/docs/ssh), [Render environment variables](https://render.com/docs/environment-variables).

Place the Render service and Neon project in nearby regions (for a UK demo, Render Frankfurt and Neon Frankfurt are the sensible starting point). Render supports Oregon, Ohio, Virginia, Frankfurt, and Singapore, but a service/database region cannot be changed in place; cross-region private networking is unavailable. Neon compute automatically suspends after five minutes idle and wakes on the next query, so the first request after an idle period can be slower. Sources: [Render regions](https://render.com/docs/regions), [Neon compute/scale-to-zero](https://neon.com/docs/manage/endpoints/), [Neon regional latency](https://neon.com/demos/regional-latency).

## Other candidates checked (not selected)

**Railway** now advertises a $0 Free plan with only $1/month of resource credit, 0.5 GB RAM per service, and 0.5 GB volume storage. Its stated prices are $10/GB-month RAM, $20/vCPU-month CPU, $0.15/GB-month volume, and $0.05/GB egress; a continuously running Django service plus a Postgres service therefore exceeds the $1 credit. The no-card $5 trial is one-time and expires after 30 days; Trial stateful volumes are deleted 30 days after expiry. Sources: [Railway plans](https://docs.railway.com/pricing/plans), [Railway pricing](https://docs.railway.com/pricing), [Railway free trial](https://docs.railway.com/pricing/free-trial), [Railway Postgres](https://docs.railway.com/databases/postgresql). **Not genuinely zero-cost for this two-service architecture.**

**Fly.io** was excluded because its current docs explicitly say there is no free account/free tier, all normal organizations require a card, and the remaining free trial is only 2 VM-hours or seven days. Sources: [Fly.io pricing](https://fly.io/docs/about/pricing/), [Fly.io free trial](https://fly.io/docs/about/free-trial/).

## Unavoidable user-owned actions

1. Create or use a GitHub account/repository and authorize Render (or Koyeb) to read it; push the ShelfSum source and deployment configuration.
2. Create a Neon Free account/project, choose a region, set the database password, and copy its PostgreSQL connection string. No card is advertised for Neon Free.
3. In Render (primary), create the Free Web Service, select the Python runtime, set build/start commands, and add `DATABASE_URL`, `SECRET_KEY`, and any deployment-specific settings as environment variables. The user must keep these credentials private.
4. Run deployment via `build.sh` (which installs dependencies, collects static assets, applies migrations, and runs deterministic Demo seeding to verify and preserve the canonical dataset without duplicating records while resetting published Demo passwords); verify the public URL, health endpoint, and Demo exploration.
5. Maintain a small backup/export of the demo database and monitor Neon storage/compute quotas. A custom domain is optional and intentionally omitted.

## Bottom line

**Primary:** Render Free Web Service + Neon Free Postgres, preferably both in Frankfurt. It meets public HTTPS, off-PC operation, persistent Postgres, migrations/static files/secrets, and demo seeding with no AI or paid API; only the web cold start and Neon free quota need monitoring.

**Fallback:** Koyeb Free Web Service + Neon Free Postgres. Use it if Render cannot provision the service or the Render account is unavailable, accepting Koyeb's mandatory card validation and one-hour scale-to-zero behavior.
